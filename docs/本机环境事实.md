### 安装留痕：ffmpeg 是本轮新装的（2026-09-26）

装前 `/usr/bin/ffmpeg`、`/usr/local/bin/ffmpeg`、`/snap/bin/ffmpeg` 三处**均不存在**，`vt_pipeline.py probe` 退出码为 **2**（主路线不可用）。

```bash
sudo apt-get install -y ffmpeg      # 候选 7:8.0.1-3ubuntu2；实装 102 个包 / 187 MB，退出码 0
```

> ⚠️ **沙箱约束（重要，勿重复踩）**：安装**必须**在正常 WSL shell（或放宽权限的会话）内执行。
> 受限沙箱会话把根文件系统挂为**只读**并置 `no_new_privs=1`，此时 `sudo` 会直接报
> `The "no new privileges" flag is set, which prevents sudo from running as root`，
> 且 `/usr/local/bin` `$HOME/.local/bin` 均不可写——这**不是** ffmpeg 的问题，是沙箱边界；
> 强行重试同一命令只会重复失败。判据：`grep NoNewPrivs /proc/self/status` == 1 即受限。

## 三、宿主 ASR 的真实返回语义（实测，调用方必须按此判成败）

| 情形 | HTTP | 响应体 |
|---|---|---|
| 成功 | 200 | `{"ok":true,"text":"…"}` |
| PCM 数据非法 / 非 16k wav | 200 | `{"ok":false,"code":"ASR_LOCAL_FAILED","message":"Cannot read properties of null (reading 'sampleRate')"}` |
| 缺 `data:audio/wav;base64,` 前缀 | 200 | `{"ok":false,"code":"BAD_AUDIO"}` |

> **判据：必须看 `ok` 字段，不能看 HTTP 状态码**（失败也是 200）。`vt_pipeline.py` 已按此判并抛错。
> 30s 音频实测 5.6–12 秒；314 秒音频切片后总耗时约 100 秒。

## 四之二、历史帧 OCR 发现**静默失败**（2026-09-25 复验，仍有效）

**现象**：`samples/BV1JMbp6MEo5/帧OCR原始结果.md` 16 帧中有 **8 帧记为空白**（50%），
其中 `[02:20]/[02:40]/[03:00]` 三帧在成品文案 L104 被引为「画面可见 `检索情景记忆` 等 5 项」。

**复验**（不采信归档结论，重下视频重抽帧重跑 OCR）：
1. 按同一规则重抽帧（`fps=1/20, scale=1280`）得 16 帧；
2. 争议三帧的**图像体积 61.8 / 53.8 / 76.6 KB** —— 有实质内容，**不是空屏**（空屏通常 <30KB）；
3. `qwen3.5:9b` 重跑 OCR，三帧**均输出大量文字**：

| 帧 | 时刻 | 重跑 OCR 实际内容（节选） |
|---|---|---|
| f_008 | [02:20] | `用户表达需求` / `LLM` / `PostgreSQL` / `第一次交流(保存偏好)` / `检索用户记忆` / **`用户提问`** / `最近有什么耳机推荐？` |
| f_009 | [02:40] | `耳机没有声音` / **`第一次交流(保存经历)`** / `PostgreSQL` |
| f_010 | [03:00] | **`继续处理昨天那副耳机？`** / **`检索情景记忆`** / `用户提问` / `第二次交流` / `上次排查无效` |

**结论**：成品断言**为真**；故障在**归档环节——原 OCR 静默失败**（把有内容的帧记成空），
导致证据链断裂、后续无法自证。**这与 ASR 的假绿同族：接口没报错 ≠ 结果达成。**

> **卫生规则（新增）**：抽帧 OCR 后必须做**空帧率守检**——空帧占比 > 1/3 时须先质疑
> 「OCR 是否静默失败」再下「画面无文字」的结论；机检见 `scripts/check-content.py` 的 C6 守卫。
> 空帧不等于画面无文字；静默失败会让「无文字」判据假绿。

## 七、环境事实的维护纪律

1. **本表会过期**。服务是否在跑、路径是否存在，引用前**必须重测**。
2. **每轮实测后更新本表**，写明实测日期与命令；不要抄旧结论。
3. 教训：文档写"✅ 可用"而机器上早已不存在，按文档操作**直接失败**——文档本身看起来毫无问题，
   这就是「**假绿**」：不是记录错误，是**记录未复验**。
4. 连带教训（2026-09-25）：用**文本正则**扫「是否依赖某库」会同时产生假绿与假红
   （注释里出现库名即误报）。判据要落在**结构化事实**上（如 AST 解析出的 import 语句）。
5. 迁移教训（2026-09-26）：环境整体迁移（Windows → WSL）后，**旧档不是"稍旧"而是"整档失效"**。
   本档上一版所有解释器路径均指向 Windows 文件系统，在 WSL 内**一条都不可用**；
   此类档在迁移后应视为**作废重测**，而不是"更新个别数字"。
6. 判据须看**退出码**：`probe` 的可用性以退出码为准（0=可用 / 2=环境不可用）。
   用管道（如 `| head`）测量会取到管道的退出码而非本体的，**管道会遮蔽真实退出码**。
