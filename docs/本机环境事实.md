## 四、环境事实的维护纪律

1. **本表会过期**。环境侧事实（服务是否在跑、路径是否存在）会自己变化，引用前**必须重测**。
2. **每轮实测后更新本表**，并写明实测日期与命令；不要抄旧结论。
3. 上一版的教训：文档写"✅ 可用"但机器上早已不存在，导致按文档操作**直接失败**——而文档本身看起来毫无问题。
   这正是「**假绿**」：不是记录错误，是**记录未复验**。

## 五、可复现的最小命令集

```powershell
# 0) 前置检查：ASR 服务活着吗
curl.exe -s http://127.0.0.1:3082/health
#    → {"ok":true,"modelReady":true,"model":"sense-voice"}

# 1) 元数据 + 音频地址（B站，无需 cookie）
#    GET https://api.bilibili.com/x/web-interface/view?bvid=<BV>
#    GET https://api.bilibili.com/x/player/playurl?bvid=<BV>&cid=<cid>&fnval=16
#        → data.dash.audio 中挑最低 bandwidth（本例 id=30216 / 65kbps / 2.5MB）
#    请求头必带：Referer: https://www.bilibili.com/

# 2) 转 16k 单声道 wav（SenseVoice 要求 16k）
ffmpeg -y -i audio.m4s -ar 16000 -ac 1 -c:a pcm_s16le audio.wav

# 2b) 需要时间轴时，先切片再做整段（注意：**不要用手写的 WAV 头拼接**）
ffmpeg -y -i audio.wav -f segment -segment_time 30 -c copy s_%02d.wav

# 3) 转写（POST /rpc）
#    {"method":"transcribe","args":{"audioBase64":"data:audio/wav;base64,<...>","language":"zh"}}
#    → {"ok":true,"text":"..."}

# 4) 画面抽帧 + 本地视觉 OCR
ffmpeg -y -i video.m4s -vf "fps=1/20,scale=1280:-1" -q:v 3 frames/f_%03d.jpg
#    POST http://127.0.0.1:11434/api/chat  {model:"qwen3.5:9b", messages:[{content:<提示词>, images:[<b64>]}]}
```

> ⚠️ **踩坑记录**：手写 44 字节 WAV 头 + 直接拼 PCM 切片，会让 sherpa-onnx 报
> `Cannot read properties of null (reading 'sampleRate')`（写出来的头里 RIFF size / data size 与实际不符，
> 且 ffmpeg 生成的原始 wav 带 `LIST` 块，头不是标准 44 字节）。**改用 ffmpeg `-f segment` 切分**即可。
