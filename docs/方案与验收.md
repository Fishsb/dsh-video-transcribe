# 方案与验收（形态收敛）

> 状态：**方案态**（未经具名授权，不施工）。
> 本档按「方案 ⟷ 验收成对」原则组织：每个板块给出**做什么**与**怎么判它成了**，验收一律要求可核验证据而非自述结论。

---

## 〇、先说结论：推荐「技能为正本，插件只做胶水」

| 方案 | 内容 | 推荐度 |
|---|---|---|
| **A. 纯技能** | 只维护 `skill/`，靠现有工具（ffmpeg/curl/fetch）驱动，不碰 DSH 内核 | ⭐⭐⭐ 最低成本 |
| **B. 技能 + 插件（推荐）** | `skill/` 是流程正本；插件只提供**三个工具**：`vt_transcribe` / `vt_metadata` / `vt_frames`，内部调用既有 :3082 与 :11434 | ⭐⭐⭐⭐ **首选** |
| **C. 全插件** | 把下载、转写、OCR、纠正全部塞进插件 | ⭐ 不推荐（与宿主已有能力重复，违反"不冗余堆叠"） |

**为什么推荐 B**：本机**已经**有 ASR worker（:3082）与视觉模型（Ollama :11434）。插件再内嵌一套引擎就是平行能力、双份维护。
插件的真正价值只有一点：**把"操作步骤"变成"一次工具调用"**，让流程不依赖模型记不记得住命令。

## 一、板块划分与验收

### 板块 1 · 技能整理（修技术债）

**做什么**：`skill/SKILL.md` 与 `skill/scripts/video_text_extract.py` 里仍写死本机路径（hermes venv / `C:\Users\lk\bin\BBDown\`），且这些路径**实测已失效**。改为运行时探测 + 环境变量覆盖，并把失效的路线（faster-whisper / BBDown / yt-dlp）降级为"可选适配器"。

**验收**：
1. 全仓 `grep -rn "C:\\\\Users\\\\lk" skill/ scripts/` **零命中**（机检，非人眼）。
2. 在**未装 faster-whisper / 无 BBDown / 无 yt-dlp** 的环境下，`skill` 主链路仍能跑通至少一次 B站样例。
3. `samples/` 里既有样例重新回归，产物与既有产物**语义一致**（人工比对 + 关键字段 diff）。

### 板块 2 · 视频信息获取层

**做什么**：把"B站元数据 + 音频地址 + 评论 + 弹幕"四件事收敛为一个可复用实现（当前散在临时脚本里）。

**验收**：
1. 对 `BV1JMbp6MEo5` 重跑，产出 `info.json` 字段数与现有样件**一致或为超集**（`jq` 比对键集合）。
2. 弹幕为空的视频须**显式输出 `danmaku_count: 0`**，不得静默缺字段（"无输入"必须可见）。
3. 无需登录 cookie 即可完成。

### 板块 3 · 转写层

**做什么**：封装 :3082 worker 的调用（整段 + 分段两条），含 30 秒切片与时间轴输出。

**验收**：
1. 对样例音频，整段稿与 `samples/BV1JMbp6MEo5/原始转写.txt` **一致或更优**（以错字数计，人工抽 20 句核对）。
2. 分段稿**段数与切片数相符**，且时间戳与切片边界严格对应（`段数 == ceil(时长/30)`）。
3. 切片走 `ffmpeg -f segment`，**不得**手写 WAV 头（已踩坑，见《本机环境事实》§五）。

### 板块 4 · 二次纠正层（**本项目的核心价值**）

**做什么**：把"三方交叉纠正"固化成流程：元数据标签 + 评论区 + 画面 OCR，逐条给依据。

**验收**：
1. 成品文案的《整理说明》纠错表**每条都有依据列**；依据为空的条目须显式标注「推断」。
2. 抽 5 条修正，逐条回原帧/原元数据**人工复核成立**（可核验，不看结论看证据）。
3. **反例验收**：故意喂一份"无画面文字、无评论"的视频，成品**不得**编造画面信息（应输出空栏目 + 说明）。

### 板块 5 · 插件壳（方案 B 的落地形态）

**做什么**：三个工具 `vt_metadata` / `vt_transcribe` / `vt_frames`，薄封装既有能力。

**验收**：
1. `dev_plugin_status` 显示插件已装配，三个工具在 tools schema 中可见。
2. 三工具各跑通一次，返回结构化 JSON（非自由文本）。
3. **卸载即净**：`dev_uninject_plugin` 后工具消失、无残留路由、无残留监听。
4. 插件源码内**不重复实现**任何转写/OCR 引擎（机检：不得出现 sherpa-onnx / onnxruntime 依赖）。

### 板块 6 · 样例回归

**做什么**：`samples/` 作为回归基线，每次改链路后重跑一个样例。

**验收**：
1. 新增样例**只增不改**，历史样例 sha256 不变（机检）。
2. 回归脚本能一键跑完并从产物出结论（不是"跑完了"而是"对了/错了"）。

## 二、总验收（整体达成判据）

| # | 判据 | 证据形式 |
|---|---|---|
| 1 | 零硬编码本机路径 | `grep` 零命中的命令输出 |
| 2 | 全链在一台"只有 ffmpeg + 本机 ASR"的机器上跑通 | 实跑日志 + 产物 |
| 3 | 每个修正都有依据 | 纠错表（含"推断"标注） |
| 4 | 无证据不编造 | 反例样例（空画面/空评论）产物 |
| 5 | 插件卸载即净 | 卸载前后 `dev_plugin_status` 对比 |
| 6 | 样例可回归 | `python scripts/check-regression.py --e2e` 输出 PASS/FAIL/SKIP 清单，退出码 0 |

> **#6 已落地（2026-09-25）**：`scripts/check-regression.py` 一键跑完 R1–R4 并给结论，不用人看日志：
> ```powershell
> $env:VT_UPSTREAM_ORIGIN = "D:\lk\Video-Transcribe"   # 不设则 R2 显式 SKIP（不计通过）
> python scripts/check-regression.py --e2e
> ```
> 三态纪律：**SKIP 不计通过**（退出码 2 = 有待办，不是绿）。已自证：篡改样例 → exit 1；未设原件目录 → exit 2；全绿 → exit 0。

## 四、已知风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| ASR worker 是**别的插件的资产** | `:3082` 属 `dsh-prompt-enhancer-asr`；它被卸载/改端口则本项目失效 | 运行时探测 + 环境变量覆盖端口；不可达时给出明确报错而非静默失败 |
| SenseVoice 对**中英混说**可能弱 | 样例中 Codex/trace/SOP 靠画面纠正才修对 | 二次纠正层就是为此存在；画面 OCR 不可省 |
| 长视频转写慢 | 实测 1.5× 实时（单线程 CPU） | 分段跑 + 后台任务；或向 worker 加 `num_threads`（须改他人插件，需授权） |
| 画面 OCR 可能误读 | 视觉模型对生僻字/代码易错 | 交叉验证；重要专名标「存疑」 |
