# Video Transcribe · 视频文案提取

把一条视频链接变成**可用的文案**：先拿字幕，拿不到就本地转写，再用视频自身的元数据、评论和画面把转写稿校正成稿。

面向的是这类场景：你看到一个讲得不错的视频，想把内容留下来——做笔记、写文章、进知识库、发给别人看。字幕是零误差的，但它常常没有；自动转写人人都有，但专名、术语、断句往往错得没法直接用。这个项目的价值就在**后半段**：让转写稿变成能读的稿子。

## 同类项目与差异

| 项目 | 定位 | 与本品差异 |
|---|---|---|
| [qkirara/Video-Transcribe](https://github.com/qkirara/Video-Transcribe) | YouTube/B站转写，字幕优先 + ASR + LLM 纠错 | 本品的上游基座，已整包归档于 `upstream/` |
| [VanillaCoca/video-script-tool](https://github.com/VanillaCoca/video-script-tool) | 图形界面 + 命令行，B站/YouTube 字幕或 Whisper 转写 | 同样是"转写 + 字幕优先"，较少涉及元数据/画面交叉校正 |
| **本品** | 转写**只是中间产物**，目标是三层结构的成品文案 | ① 三层信息组织：纠错正文 + 评论/弹幕标注 + 画面补充<br>② 与 DSH 宿主集成本地 ASR，无需联网、无需 API Key<br>③ 纠正环节的证据链来自视频自身（标签/评论/画面 OCR），不靠模型硬猜 |

## 工作链路

```
输入视频链接
  │
  ├─ ① 元数据采集    标题 / 简介 / 标签 / UP主画像 / 评论区
  │                  → 这既是语境，也是后续纠错的"参考答案"
  │
  ├─ ② 字幕检索      有字幕 ──▶ 直接用（零误差，秒级）  ← 优先路线
  │                  无字幕 ──▶ 继续
  │
  ├─ ③ 音频获取      官方接口取最低码率音轨（体积小 ~90%）
  │
  ├─ ④ 本地转写      sherpa-onnx + SenseVoice（CPU 可跑，离线，免 Key）
  │                  整段稿 + 30 秒切片稿（带时间轴）
  │
  ├─ ⑤ 二次纠正      ┌ 元数据标签  ┐
  │                  ├ 评论区内容  ├─▶ 三方交叉，逐条给依据
  │                  └ 画面 OCR   ┘
  │
  └─ ⑥ 出稿          最终文案.md + 原始转写 + 元数据档 + 帧 OCR 原始结果
```

三条优先级原则：

1. **字幕 > 转写**——字幕零误差，转写只是拿不到字幕时的兜底。
2. **元数据在下载前就抓**——标题/标签/评论本身就是整理文案时的参考答案。
3. **本地转写、证据纠正**——本地模型快且免费，纠正环节由大模型做精修，但**每条修正都要能指出依据**（来自画面文字或元数据），不靠猜。

## 成品长什么样

一份最终文案分四层，读者从上往下读即完整理解：

```markdown
# <视频标题>
> 来源 / UP主 / 时长 / 方法 / 数据清单

## 一、章节名
<纠正后的正文段落>
> 💬 弹幕/评论标注（⚠️ 争议优先）
## 二、章节名
...
## 画面信息补充（AI 识图）
| 时间点 | 画面文字 | 对应章节 |
## 整理说明
1. 转写纠错表（逐条给依据）
2. 数据来源清单
3. 标注规则执行情况
```

**原文一字不改**：评论标注与画面补充都是附加层，正文段落独立呈现。

## 目录结构

```
video-transcribe/
├── skill/            技能本体（可直接给 Agent 装载）
│   ├── SKILL.md
│   └── scripts/      单脚本完整链路实现
├── upstream/         上游项目纯副本（保持可对账，不在此目录内改）
├── docs/             方案档 · 资产盘点 · 本机环境事实 · 方案与验收
├── samples/          实证产物（每个视频一个目录，含成品与原始稿）
└── scripts/          本项目自有工具脚本
```
